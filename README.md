# 麦门告解室 · McDonald's Confessional ⛪🍟

> 「感情归你，数字归我。」——审计官
> 「没有人天生就是罪人，只是没人替他算过账。」——辩护律师

一个跑真数据的**消费审判 Agent**。它不只告诉你吃了多少卡，而是回答三个更难的问题：

1. **你白扔了多少钱？** —— 逐单核价，算出每笔订单「本该花多少」，差额归因到「没用券 / 券没用到位 / 规格不划算」
2. **亏在哪、亏多少？** —— 券 + 套餐组合优化（位掩码 DP 精确求解），不是模型口算
3. **下次怎么办？** —— 四角色开庭定罪，下达**可执行**的赎罪计划（每日 60 分钟，多少天走完），并盯着你打卡

## 一场真实庭审长什么样

以下是 `python -m src.cli trial` 的真实输出（内置虚构档案）：

```
【开庭】
本庭受理被告在过去 332 天内的 7 笔麦当劳消费，涉案金额 333.00 元，累计摄入 6731 千卡。

【审计官陈词】
「感情归你，数字归我。」
经逐单复核：按当前券池的最优组合，7 单里有 3 单本可以更便宜。
实付合计 333.00 元，理论最优合计 311.50 元，差额 36.00 元（占实付 10.8%）。
亏损最重的一单：2026-03-19 19:05:31 于北京朝阳大悦城餐厅，实付 122.00 元，
最优价 100.00 元，白扔 22.00 元。

【辩护律师抗辩】
1. 当事人曾主动选择无糖饮品，具备向善意愿（依据：共 1 单出现过无糖选择）
2. 当事人并非挥霍之人，多数订单已在主动使用优惠（依据：57% 的订单实付低于菜单原价）
3. 消费频次有节制，并非沉溺（依据：332 天内仅 7 单，平均 47.4 天一次）
...
【合议量刑】
基准刑：热量赎罪 约 1.2 天 + 亏损罚金赎罪 约 6.0 小时
采纳辩护 4 条，减刑 20%：✓ 无糖选择 ✓ 主动用券 ✓ 频次节制 ✓ 零亏损完美订单
驳回 2 条，理由：证据不足或属普遍行为，不构成减刑事由。
最终赎罪义务：约 1.1 天

【执事登记】
赎罪计划：每日步行 60 分钟，预计 27 天完成。
打卡方式：对执事说「打卡 60 分钟」。
```

注意两个细节：**辩护会被驳回**（不是全盘照收），**刑期取决于数据**（不同人的账单审出不同结果）。

## 架构：三层分工

```
MCP（取数） → Python（算术） → Agent prompt（表达）
```

组合优化、核价、亏损归因、量刑全部由 `src/` 里的代码算，prompt 只负责把这些数字说成人话。
这样改文案不会改错数字，改算法也不用动文案。

## 数据边界（哪些是真的，哪些是快照）

| 数据 | 来源 | 性质 |
| --- | --- | --- |
| 订单、营养、卡包券 | `order-list` / `list-nutrition-foods` / `query-my-coupons` | 真实调用 MCP |
| 菜单价 | `src/demo_data.py` 内置快照 | **演示用**，接 `calculate-price` 后替换 |
| 审计金额 | 本地组合优化按当前券池重算 | **反事实估算**，不等于「你当时真的多花了」 |
| 自测结果 | `.github/workflows/ci.yml` | 每次 push 自动跑，见仓库 Actions 页 |

菜单价与审计口径是本项目最薄弱的两环，写在这里而不是藏在角落。

## 四个角色

| 角色 | 口头禅 | 干什么 |
| --- | --- | --- |
| **审计官** | 感情归你，数字归我 | 逐单核价，把亏损摆上台面 |
| **辩护律师** | 没有人天生就是罪人 | 从真实数据找减刑情节（每条减刑 5%，上限 30%） |
| **告解师** | 本席不同情你，但本席理解你 | 盘问异常订单、定罪、量刑、写批注 |
| **执事** | 判决书签了字，就得走完这段路 | 登记账本、下达赎罪计划、盯打卡、券到期预警 |

## 主动提醒（Agent 与工具的分水岭）

配套三个定时任务，详见 [`docs/automations.md`](docs/automations.md)：

- **晚祷** 每晚 22:00：「今夜还要下单吗？你的赎罪还剩 X 分钟」
- **券预警** 每天 10:00：「赦免凭证将于 X 小时后失效」
- **结案陈词** 每周日 21:00：本周罪案汇总 + 一句判词

## 快速开始

```bash
git clone https://github.com/hanzhe-one/mcd-confessional.git
cd mcd-confessional

python -m src.cli trial --save    # 开庭（虚构档案，零配置零 Token）
python -m src.cli audit           # 只看审计：逐单亏损与归因
python -m src.cli checkin -m 60   # 打卡赎罪 60 分钟
python -m src.cli ledger          # 查账本与赎罪进度
python -m src.selftest            # 跑自测（15 项）
```

接你自己的真实数据：

```bash
export MCD_MCP_TOKEN=你的Token       # Windows: $env:MCD_MCP_TOKEN="..."
python -m src.cli trial --live
```

MCP 配置见 [`mcp-config.example.json`](mcp-config.example.json)（Token 只允许环境变量占位）。

## 审计口径（必须说清楚）

审计官算的是**反事实**：把历史订单的餐品，用**你当前卡包里的券**重新跑一次组合优化，
得到「如果当时有这些券、且用到最优，本该花多少」。所以：

- ✅ 差额是**真实算法算出来的**，不是编的
- ⚠️ 但它是「本可以更便宜」的估计，不等于「你当时真的多花了」——当时可能没有这些券
- ⚠️ 菜单价使用演示快照，真实价格以门店实时返回为准（接 `calculate-price` 后可替换）

这个口径写在代码里（`src/audit.py` 顶部）和 SKILL.md 里，不玩文字游戏。

## 目标用户

| 人群 | 他们得到什么 |
| --- | --- |
| **觉得自己"没乱花钱"的人** | 一份逐单核价的审计，看看到底白扔了多少 |
| **优惠券放到过期的人** | 「赦免凭证将于 X 小时后失效」比推送通知好使 |
| **想复盘年度消费的打工人** | 可截图分享的告解证书 + 完整庭审记录 |
| **喜欢把自律游戏化的人** | 罪恶账本、赎罪打卡、连续天数 |
| **开发者** | 一个真实可跑的组合优化 + 多角色 Agent 编排范例 |
